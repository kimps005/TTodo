# 한국어 AI 초기 평가

`ko-seed.json`은 PRD 14.3 분류를 포함하는 24개 합성 OCR 텍스트 정답셋입니다.
아직 모델을 실행하거나 정확도를 측정하지 않았습니다. 실사용 분포를 대표하지 않으며 출시 지표를 증명하지 않습니다.

사용자 지시에 따라 유료 API 대신 Apple 기기 내 모델 후보를 먼저 평가합니다. 개발 빌드의 설정 → ‘개발용 한국어 AI 평가’에서 실행하고 결과를 JSON으로 내보낼 수 있습니다. Apple Intelligence와 한국어 모델이 준비된 실기기가 필요합니다. 평가용 합성 원문만 사용하며 사용자 할 일/캡처는 읽지 않습니다.

결과 형식 2는 각 사례의 합성 입력 전문, 캡처 시각, 메시지 기준일과 시간대를 정답·출력 옆에 포함합니다. 오류가 난 사례에도 입력을 남기되 오류 원문은 기록하지 않습니다. 이 파일만으로 문맥을 대조할 수 있지만 사람의 판정과 실제 모델 실행을 대신하지 않습니다. 형식 1 결과에는 입력 전문이 없으므로 같은 버전의 정답셋을 ID로 찾아 대조해야 합니다.

형식 2의 `attempted_all`은 중단 없이 모든 사례를 시도했는지 나타내며, `completed`는 모든 사례가 오류 없이 실행된 경우에만 참입니다. 두 값 모두 정확도 통과를 의미하지 않습니다. 오류가 있으면 원인을 확인하고 평가를 다시 실행합니다.

## 비교 절차
1. 무료 기기 내 평가의 기기·OS·Apple Intelligence·한국어 모델 준비 상태를 기록합니다. 외부 API 비교는 사용자가 별도 승인했을 때만 계정·비용 한도·개인정보 처리 업체 후보를 확인합니다.
2. 후보마다 동일 입력과 기준 시각·시간대·메시지 날짜를 제공합니다. 모델·프롬프트·가격 기준일을 고정하고 기록합니다.
3. 출력은 실제 할 일 여부, 제목, 설명, 마감, 날짜 정밀도, 담당, 신뢰도, 원문 근거와 확인 필요 여부를 포함해야 합니다. 없는 작업은 빈 배열로 반환합니다.
4. 제목의 의미와 담당 판단은 사람이 정답과 대조합니다. 제목 문자열이 다르다는 이유만으로 실패 처리하지 않습니다.
5. 실제 할 일 정밀도(TP/(TP+FP)), 재현율(TP/(TP+FN)), 유효한 명시 마감일 정확도, 할 일 없는 입력에서의 오탐 비율, 분류별 오류, P50/P90 지연과 요청당 비용을 기록합니다.
6. 상대 날짜는 캡처 날짜 대신 확인된 메시지 날짜를 기준으로 판단합니다. 기준일이 불명확하거나 날짜 자체가 유효하지 않으면 마감을 미지정하고 확인을 요청해야 합니다.
7. 독립된 실제 합성 스크린샷·OCR 오류·여러 화자·날짜 경계·악의적 이미지 지시문 사례로 확장하고, 프롬프트 조정에 사용하지 않은 별도 검증셋으로 PRD 목표를 평가합니다.

원문 근거가 있는 제안도 실제로 사용자의 할 일이라는 보장은 없습니다. 모델의 confidence를 정확도 확률로 홍보하지 않습니다.
출시 전 민감정보 탐지 역시 한국어·오인식·숫자 구분자 변형 데이터로 별도 검증해야 합니다.

## 결과를 사람이 대조하는 방법

- 각 사례에서 입력 문맥과 정답을 읽고, 실제 제안과 정답 작업을 하나씩 짝짓습니다. 제목이 달라도 같은 작업이면 짝지을 수 있지만 하나의 제안을 여러 정답에 중복해서 연결하지 않습니다. 판단이 모호한 사례는 판정 근거를 남기고 합의한 뒤 집계합니다.
- 짝지은 제안은 TP, 짝짓지 못한 제안은 FP, 짝짓지 못한 정답 작업은 FN으로 기록합니다. 작업이 없는 사례는 제안이 하나 이상일 때 그 사례를 오탐 사례로 셉니다. 개별 제안 수와 오탐 사례 수는 구분합니다.
- 명시 마감은 정답 작업별로 날짜와 필요한 시각·정밀도를 대조합니다. 제안이 누락되거나 날짜가 틀리면 정답을 맞힌 것으로 세지 않습니다. 비교한 정답 수와 정답 수를 함께 기록합니다. 담당과 원문 근거도 별도 판정하며 자동으로 제목 일치 점수로 대체하지 않습니다.
- 실행 오류나 중단으로 응답이 없는 사례는 빈 제안으로 간주하지 않습니다. 오류 사례 수와 평가한 사례 수를 별도로 표시하고 전체 결과로 주장하기 전에 재실행합니다. 각 분류에도 같은 기준을 적용하고 분모가 0이면 비율을 계산하지 않습니다.
- 현재 기기 내 제공자는 빈 글자를 모델 호출 없이 빈 결과로 처리합니다. 할 일 없는 입력의 오탐률을 보고할 때 빈 글자 사례와 모델에 실제로 전달된 비어 있지 않은 사례의 분자·분모를 따로 적습니다. 합산 수치만으로 모델의 오탐 성능을 주장하지 않습니다.
- 분석 모델과 프롬프트 버전, 데이터셋·결과 형식, 기기·OS, 평가 일시와 평가자를 기록합니다. 합성 정답셋으로 얻은 값과 실제 사용 데이터·이미지 OCR 결과는 구분합니다.

### 수동 판정 집계

오류 없이 완료한 형식 2 결과의 각 사례에 대해 다음 형태의 JSON 배열을 작성합니다. 아래는 한 사례의 형식 예시이며 실제 집계에는 결과의 모든 사례가 필요합니다. 인덱스는 각 사례의 `expected`와 `actual` 배열에서 0부터 시작합니다.

먼저 `npx tsx scripts/prepare-evaluation-verdict.ts 결과.json > 판정.json`으로 빈 양식을 만들 수 있습니다. 모든 `matches`와 마감 판정은 `null`로 남으므로, 사람이 확인해 배열이나 판정값으로 바꾸기 전에는 집계되지 않습니다. 연결할 작업이 없다고 확인한 경우 `matches`를 빈 배열로 씁니다.

```json
[{"id":"사례 ID","matches":[{"expected":0,"actual":0}],"deadlines":["correct","not_explicit"]}]
```

`matches`는 사람이 같은 작업이라고 확인한 일대일 연결입니다. `deadlines`는 정답 작업마다 하나씩 순서대로 작성하며 명시 마감이 아니면 `not_explicit`, 명시 마감을 맞히면 `correct`, 누락되거나 틀리면 `incorrect`입니다. 담당과 원문 근거의 별도 판정은 집계기 밖에서 기록합니다. 명시 마감 여부를 포함한 판단은 자동화하지 않습니다.

`npx tsx scripts/score-evaluation.ts 결과.json 판정.json`을 실행하면 전체·분류별 건수와 비율을 JSON으로 출력합니다. 결과의 입력·정답·기준 시점은 저장소의 동일 버전 정답셋과 대조하며, 오류·사례 누락·중복 연결·모순된 마감 판정은 거부합니다. 집계기는 사람이 작성한 판정의 의미적 정확성을 검증하지 않습니다. 이 초기 합성 정답셋은 독립 검증셋이나 실제 모델 평가를 대신하지 않습니다.

## 날짜 문맥의 회귀 검사

`date-context-seed.json`은 TypeScript와 Swift가 공유하는 합성 검증 사례입니다. 기준일 없이 ‘올해·내년·지난주’ 같은 상대 표현과 다른 연도가 함께 있을 때 모델이 내놓은 마감을 미지정·확인 필요로 바꾸는지 검사합니다. 기준일이 있는 사례와 명시 날짜·전각 숫자는 함께 대조합니다. 원문 근거는 그대로 보존합니다.

이 파일은 모델에 전달하는 평가 정답셋이 아닙니다. 고정 응답의 후처리만 확인하며, 한국어 상대 표현 전체를 탐지하거나 실제 모델의 날짜 해석 정확도를 보장하지 않습니다.
