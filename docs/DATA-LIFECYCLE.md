# 데이터 처리와 삭제 검토안

기준일: 2026-11-14. 현재 저장소 구현을 정리한 개발 검토용 문서다.
사용자가 운영자 이름/상호와 공개 지원 이메일을 ‘미정’으로 답했다. 최종 공개 개인정보 처리방침과 지원 페이지는 해당 정보 확정 후 준비한다.

## 처리 흐름

직접 입력한 할 일은 기기에 저장한다. 사진 선택·공유 메뉴·단축어가 직접 전달한 이미지에서 기기 내 OCR을 수행하고, AI 분석 동의가 있으면 Apple 기기 내 모델로 제안을 만든다. 외부 유료 AI API나 개발자 서버를 연결하지 않았다. 사용자 승인 후에만 실제 할 일을 만든다.

원본 이미지와 전체 OCR 텍스트를 분석 DB에 영구 복제하지 않는다. 제안 검토에는 판단 근거 문장만 저장한다. 민감 문자열 감지는 추가 제한 수단이며 모든 민감정보를 식별한다고 보장하지 않는다.

## 데이터별 수명

| 데이터 | 목적 | 보관과 정리 |
|---|---|---|
| 할 일 제목·메모·마감·완료 상태 | 목록과 잠금화면 표시 | 개별 삭제 또는 전체 삭제까지 |
| 미승인 제안 제목·설명·마감·담당 | 사용자 검토 | 7일이 지나면 다음 앱 접근/공유 검토 때 정리, 무시하면 즉시 본문 삭제 |
| 저장된 제안의 제목·설명·마감·담당 | 분석 처리 이력 | 연결 할 일 개별 삭제 시 함께 삭제, 전체 삭제 시 제거 |
| 원문 근거 문장 | 추출 판단 확인·최근 유사 분석 안내 | 최대 7일 후 다음 접근 때 정리. 무시한 제안·연결 할 일 개별 삭제·AI 동의 철회·전체 삭제 경로에서도 정리 |
| 이미지 SHA-256 지문·제안/분석 ID·처리 상태 | 중복 처리와 승인 재전송 방지 | 본문 삭제 후에도 남기며 전체 삭제 시 제거 |
| 분석 시각·출처·모델 버전·오류 코드 | 처리 이력과 중단 복구 | 전체 삭제까지. 원문이나 사진을 오류 로그에 넣지 않음 |
| 표시 수준·AI 동의 등 설정 | 사용자 선택 적용 | 변경 또는 전체 삭제까지 |
| 선택 사진 임시 파일 | 현재 선택/검토 미리보기·OCR | 화면 종료 시 정리, 앱 중단 잔여 파일은 다음 시작 시 정리 |
| 공유창 축소 미리보기 | 해당 공유창에서 사진 확인 | 메모리에 유지하며 확장 종료 시 해제 |
| JSON 내보내기 임시 파일 | 사용자가 선택한 공유 대상에 전달 | 공유 종료 또는 다음 시작/전체 삭제 시 캐시 정리 |

앱이 종료된 동안 정확히 7일째에 정리된다고 표시하지 않는다. 승인 시점에도 만료를 확인해 오래 열린 검토 화면에서 저장되는 것을 차단한다. 사용자가 다른 앱에 내보낸 복사본은 해당 공유 대상에서 관리한다.

사진 선택 거부·교체·검토 종료 시 파일 삭제는 앱 캐시 하위 URI만 허용한다. 사진 라이브러리 원본이나 캐시 밖 파일은 삭제하지 않는다. 캐시 경로와 접두사만 같은 폴더 및 인코딩된 상위 경로도 허용하지 않는다.

시작 시 캡처 디렉터리와 두 내보내기 임시 파일의 정리를 각각 시도한다. 한 곳의 정리 실패가 다른 파일 정리나 할 일 저장소 열기를 막지 않으며, 일부 파일이 남으면 안내하고 다음 실행에 재시도한다. 이 안내를 파일 삭제 완료로 해석하지 않는다. 실제 iOS 접근 실패·잔여 파일 수명은 기기 검증 대상이다.

## 사용자의 조작과 결과

- 개별 삭제: 할 일과 연결 제안 본문을 한 트랜잭션에서 삭제한다. saved 상태·지문을 유지해 이전 승인이나 재분석으로 복원되지 않도록 한다. 같은 캡처의 다른 항목은 유지한다.
- 제안 무시: 해당 대기 제안의 본문과 근거를 지운다. 오래된 화면/알림의 제안 ID가 현재와 다르면 새 제안을 무시하지 않는다.
- AI 중지 및 원문 근거 삭제: 동의 해제·진행 중 분석 토큰 무효화·저장된 근거 삭제를 한 트랜잭션에서 처리한다. 동의를 다시 켜도 철회 전 시작한 결과는 저장하지 않으며, 사용자가 새로 재시도해야 한다. 이미 시작한 기기 내 모델 연산 자체의 즉시 종료를 보장하지 않는다. 기존 할 일과 제안의 제목·설명은 유지되므로, 모두 지우려면 전체 삭제를 사용한다.
- 전체 삭제: 할 일·분석·제안·설정과 앱의 임시 파일을 지우고 미저장 빠른 입력도 비운다. 기존 알림 제거·Live Activity 종료·위젯 갱신을 요청한다. OS 화면 갱신 시점은 실제 기기 검증 대상이다.
- 재분석: 한 번도 저장하지 않은 캡처에 대해 기존 미저장 제안 교체를 확인받는다. 부분 저장과 저장 후 삭제도 저장 이력으로 간주하여 재분석을 차단한다.

## 기기와 외부 경계

iOS 앱·단축어·확장은 App Group 안의 같은 로컬 DB를 사용한다. DB 디렉터리는 백업 제외와 최초 기기 인증 이후 접근 정책을 설정한다. 재부팅 후 첫 인증 전 접근은 지원하지 않는다. 실제 프로비저닝·기기 파일 보호·잠금 동작은 미검증이다.

잠금화면에는 기본적으로 개수만 표시하며 제목/개수/내용 숨김을 선택할 수 있다. 원문 대화는 표시하지 않는다. 분석 알림도 표시 수준을 따르며 제목 직접 표시는 사용자가 허용한 경우에만 사용한다.

계정·친구·클라우드 동기화·광고·분석 서버를 현재 앱에 구현하지 않았다. Apple 모델 준비/다운로드와 OS 자체 처리, 사용자가 직접 선택한 파일 공유는 앱의 외부 AI 전송과 구분하여 설명해야 한다.

## 출시 전 확정과 검증

- 운영자 공개 표기·지원 이메일·정책 시행일과 공개 URL 확정.
- 앱 안에서 접근 가능한 정책 링크와 지원 안내 연결. 가짜 주소나 확정되지 않은 URL은 넣지 않음.
- Release 의존성/Privacy Manifest와 실제 네트워크 동작 확인 후 App Store 개인정보 응답 확정. 현재 문서를 근거로 신고 완료를 주장하지 않음.
- 실제 iPhone에서 개별/전체 삭제 후 알림·위젯·Live Activity 잔여 표시, 권한 거부, 재부팅과 백그라운드 동작 검사.

[Apple 심사 지침 5.1.1](https://developer.apple.com/app-store/review/guidelines/#privacy)은 앱 내/메타데이터의 정책 접근, 보존·삭제 및 동의 철회 설명을 요구한다. [App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)는 기기 내 처리와 기기 밖 수집을 구분하며, [App Store Connect 안내](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)에 따라 최종 응답을 관리한다.
