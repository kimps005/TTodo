# 온디바이스 한국어 평가 러너

## 실행

1. 서명·설치 경로가 준비되면 Apple Intelligence와 한국어 지원 모델이 준비된 iPhone에 Debug 개발 빌드를 설치한다. 현재 Windows 개발과 macOS CI를 유지하며 실기기 설치는 미완료다.
2. 설정 → 개발용 한국어 AI 평가 → 합성 데이터로 기기 내 AI 평가를 한 번 누른다. Release에서는 이 화면을 열 수 없다. 기기 내 AI를 사용할 수 없으면 화면·콘솔·리포트에 `SKIPPED_UNAVAILABLE`과 가용성 사유를 기록한다.
3. 화면의 정밀도, 재현율, 명시 마감일 정확도와 개별 오탐·누락·마감 오류를 검토한다. ‘Markdown 리포트 내보내기’ 또는 ‘JSON 리포트 내보내기’를 눌러 공유 메뉴에서 파일을 저장한다. 기기 모델명·OS·Apple Intelligence 언어/준비 상태도 실기기 QA 기록에 남긴다.

`onDeviceProvider → nativeBridge.extractTasks → AppleTodoExtractionService → OnDeviceExtraction → SystemLanguageModel.default`의 실제 제품 경로를 사용한다. 합성 OCR 텍스트만 전달하며 정답·핵심 어휘는 모델 프롬프트에 전달하지 않는다. 빈 OCR 두 사례는 제품 경로와 동일하게 모델 호출 없이 빈 결과가 된다. DB·사용자 캡처·외부 API는 사용하지 않는다. 중단 시 현재 모델 요청이 종료된 뒤 다음 사례를 시작하지 않는다. 원시 모델 요청을 즉시 취소한다고 보장하지 않는다.

## 정답과 자동 판정

- `evaluation/EvalFixtures.json`: 카카오톡 요청/다른 사람 약속/내 약속, 내일 오후 3시·이번 주 금요일·월말, 한 화면 다중 할 일, 잡담·영수증·풍경/빈 OCR 등 36개 합성 사례. 메시지 기준일과 Asia/Seoul 시간대를 고정한다. 기존 24개에 12개를 추가한 초기 분포이며 실사용 대표 표본은 아니다.
- `title_terms`: 각 그룹 안에서는 대체 표현 중 하나, 그룹 간에는 모두 제목에 있어야 한다. NFKC·공백·구두점을 정규화한다. 모델의 근거는 실제 입력의 부분 문자열이고 정답 근거와 포함 관계여야 한다. 이 조건으로 최대 일대일 매칭한다. 출력 순서에 영향받지 않고 같은 할 일을 중복 생성하면 추가 출력은 FP다. 날짜는 작업 매칭 기준에 쓰지 않는다.
- Precision = TP / (TP + FP), Recall = TP / (TP + FN). 화면 수치는 백분율이며 분모 0은 ‘측정 불가’다.
- 명시 마감 정확도 = 날짜가 맞은 정답 할 일 / 날짜가 있는 전체 정답 할 일. 누락도 오답이다. 날짜만 있는 경우 날짜와 precision이 같아야 하고, 시각이 있는 경우 precision과 UTC 순간이 같아야 한다. 불필요하게 생성한 마감도 별도 표시한다.
- 전체 36개가 오류 없이 끝나고 할 일 정밀도 90% 이상과 명시적 마감일 정확도 95% 이상을 모두 충족하면 자동 판정은 `PASS`다. 완료한 실행에서 하나라도 충족하지 못하면 `FAIL`, 오류나 취소로 평가를 끝내지 못하면 `INCOMPLETE`다. 모델을 사용할 수 없으면 실행 도중에도 `SKIPPED_UNAVAILABLE`로 기록하며 목표 판정을 보류한다. 실행 오류는 진단용 합계에 누락으로 반영한다.

자동 판정은 고정 어휘 규칙이다. 의미가 맞는 다른 요약을 오답으로 보거나 잘못된 의미를 같은 어휘 때문에 정답으로 볼 수 있다. 실제 의미 정확도는 제목·담당·원문을 사람이 대조해 검증한다. 콘솔에는 상태·가용성·사례 ID·집계·오류 인덱스만 남긴다.

## 리포트 검수

- Markdown은 PRD 목표 요약과 ‘원문 | 기대값 | 모델 출력 | 판정 체크칸’ 표를 담는다. 메시지 기준일·시간대 및 원문 근거를 함께 대조하고, 일치 항목에 체크한 뒤 불일치 이유를 메모한다.
- JSON 형식 4는 같은 실행의 합성 원문·기준 시점·정답·제품 경로를 거친 모델 출력과 빈 `review` 필드를 담는다. 검수 결과는 `tasks_correct`와 `explicit_deadlines_correct`에 `true` 또는 `false`로 기록하고 해당 없는 항목은 `null`로 둔다. 기존 수동 집계 CLI는 24개 사례를 담은 형식 2 전용이다.
- 건너뛴 실행과 부분 실행에도 요약을 내보낼 수 있다. 그런 경우 지표별 목표 판정은 `NOT_EVALUATED`다. 오류로 출력이 없는 사례는 실제 빈 할 일 배열과 구분한다.

## CI 경계와 검증 범위

`TodoExtractionServiceProtocol`은 FoundationModels를 import하지 않는다. 앱 브리지·공유 확장·App Intent는 실제 Apple 구현을 사용하고, CI의 CaptureSmoke는 프로토콜 서비스로 결정적 JSON을 주입한다. 기존 closure API도 프로토콜 어댑터로 위임한다.

- macOS `PipelineSmoke`: OCR 위치/대화 순서 전처리, 기준 요일·상대 날짜/월말(평년·윤년), 빈 결과·모델 불가 대체 경로, 큐 격리, 승인 전 미생성, 승인 중복·내용 중복 방지.
- macOS `CaptureSmoke`/`StoreSmoke`: 근거·민감정보 검증, 동의 전 호출 차단, 실행 중 동의 철회 시 저장 차단, 무시/만료 시 근거 삭제, 트랜잭션·취소·재분석 정책 등 기존 경계 검사.
- Node 테스트: 정답셋 무결성, 일대일/중복/다중 매칭, 동일 시각·날짜 precision, 누락 마감 분모, 모델 불가·오류·취소, Markdown/JSON 직렬화와 로그 비내용화, 기존 DB·동의/승인 게이트와 동의 철회 시 원문/대기 제안 삭제·저장한 할 일 유지 검사.
- 전체 품질 CI: 위 테스트와 실제 Vision 합성 OCR, Swift→TS 계약, 앱·위젯·공유 확장 **Debug** 시뮬레이터 빌드로 하네스/브리지를 컴파일·번들 검사한다. 모델 없는 CI에서 실제 생성 성능을 통과 처리하지 않는다. 이 목록은 시나리오 검증 범위이며 코드 커버리지 100%를 측정했다는 뜻이 아니다.

## 접근성 검증 구분

React Native 화면은 스크롤·자동 줄바꿈·큰 글자 시 세로 배치를 사용한다. 빠른 입력은 여러 줄로 확장하면서 키보드 완료로 제출하고, 체크 상태/편집 버튼/탭/잠금 표시 수준에 레이블·힌트·값을 제공한다. 설정 표제는 header로 읽는다. 공유 확장 SwiftUI는 기본 Dynamic Type과 ScrollView, 유연한 버튼 높이를 유지한다.

CI의 기본/최대 글자 UI 회귀는 빠른 입력의 실제 TextView를 조회한다. 시뮬레이터 테스트 통과만으로 VoiceOver의 읽기 순서와 모든 제안 카드의 잘림 없음을 확정하지 않는다. 실제 iPhone에서 목록 → 빠른 입력 → 제안 선택/제목/마감/원문/승인 → 설정 순서의 탐색, 체크 상태 읽기, 최대 접근성 글자에서 긴 한국어·키보드·스크롤을 별도로 확인해야 한다. 사용자 노트북 UI 자동화는 사용하지 않는다.
