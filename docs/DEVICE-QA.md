# Phase 0 실기기 검증표

모든 항목은 아직 미검증입니다. 체크 없이 완료로 보고하지 않습니다.
기기 모델·OS 버전·앱 커밋·설정·측정 시간·결과를 함께 기록합니다.

## 사전 준비
- Apple Team의 앱과 Widget Extension에 동일 App Group이 활성화된 개발 빌드 설치.
- 처음 앱 실행 후 수동 할 일을 저장하고 재실행해 보존 확인.
- 민감한 실제 대화 대신 합성 테스트 이미지 사용.

## 잠금화면 빠른 추가 (출시 차단)
1. 단축어 생성: ‘입력 요청’(텍스트) → ‘TTodo에 할 일 추가’에 입력 결과 전달.
2. 잠금화면에서 해당 단축어를 실행할 수 있는 시스템 진입점 연결.
3. Face ID 카메라가 얼굴을 인식할 수 없는 상태에서 잠금.
4. 단축어 입력창이 인증 없이 열리는지, 앱이 전면 실행되지 않는지 확인.
5. 입력 후 완료. 앱을 열어 정확히 한 번 저장되었는지 확인.
6. 빈 값·공백·취소·200자 초과·이모지·연속 추가·비행기 모드 반복.
7. 앱 실행 중·백그라운드·시스템 종료·사용자 강제 종료 상태 각각 반복.
8. 재부팅 직후 첫 인증 전에는 접근 불가임을 확인. 첫 인증 후 다시 잠그고 반복.

인증이 요구되면 PRD P0-01 실패입니다. 인증을 요구하는 화면 이동으로 대체하고 완료 처리하지 않습니다.

## 공유 DB와 잠금 목록
- [ ] 앱 입력 후 잠금 위젯과 큰 목록 확인; 지연과 DB 저장 성공을 구분.
- [ ] 단축어 입력 후 앱 목록 일치.
- [ ] 앱에서 빠르게 입력한 직후 키보드 완료를 누르거나 한글 조합을 확정하며 저장해도 마지막 글자·이모지·붙여넣은 문구가 빠지지 않고 정확히 한 개 저장. 실패 시 입력 내용 유지. CI의 영문 합성 입력 성공과 실제 한글 키보드 검증을 구분.
- [ ] 미저장 문구와 키보드가 열린 동안 하단 탭이 가려지지 않고 설정/분석함으로 이동. 다시 할 일 탭으로 돌아오면 미저장 문구 유지. 큰 글자 크기와 키보드 종류별로 확인.
- [ ] 설정 탭에서 앱을 백그라운드로 보낸 뒤 위젯/Live Activity를 눌러 할 일 탭으로 이동. 작성·검토 중에는 미저장 내용을 덮어쓰지 않고 화면 종료 후 이동해야 함.
- [ ] 앱과 단축어 연속 동시 쓰기에서 누락·중복·DB busy 오류 확인.
- [ ] 제목 숨기기 기본값·변경·위젯 갱신 후 개인정보 확인.
- [ ] 큰 목록 시작/수정/종료, 권한 거부, 8시간 이후 만료 및 앱 복귀 복구 확인.
- [ ] 전체 삭제 후 앱·위젯·기존 Live Activity에 이전 제목이 남지 않는지 확인.
- [ ] 전체 삭제 시 미저장 빠른 입력도 비워지고 온보딩 설정이 초기화. DB 삭제 실패 시 기존 데이터와 미저장 입력을 유지하며, 삭제 커밋 후 정리 실패 시 삭제 완료와 남은 정리 안내를 구분.
- [ ] AI 제안을 저장한 뒤 개별 할 일을 삭제. 연결 제안의 제목·설명·날짜·담당·원문이 분석함/내보내기에서 사라지고 해당 분석 알림이 제거되는지 확인. 같은 이미지의 다른 항목은 유지되어야 함.
- [ ] 삭제 전 수신한 단일 추가 알림/열려 있던 검토 화면으로 재승인해도 삭제 항목이 복원되지 않는지 확인.

## 사진과 OCR
- [ ] 한국어·영어·대화·표·세로로 긴 캡처·기울어진 사진·HEIC/PNG/JPEG 확인.
- [ ] 글자 없는 사진·흐림·대용량·잘못된 파일 처리 확인.
- [ ] 사진 선택 취소·접근 제한에서 수동 입력 유지.
- [ ] 선택한 사진만 처리하며 최신 사진 임의 조회가 없는지 확인.
- [ ] 화면 닫기 후 임시 이미지 제거. 앱 강제 종료 시 남은 캐시 정리 검증.
- [ ] 임시 캡처 디렉터리 정리 실패 시에도 두 내보내기 임시 파일을 각각 정리하고 미완료를 안내. 앱 시작 시 캐시 정리 실패가 기존 할 일 열기·오프라인 수동 입력을 막지 않아야 하며 남은 파일은 다음 시작에 재시도. 실제 iOS 파일 접근 오류는 로컬 주입 검사와 구분.

## 후속 AI 통합 후 실행
- [ ] 명시적 동의 전 외부 요청 0건.
- [ ] 민감정보 차단·네트워크 실패·재시도·알림 거부 처리.
- [ ] 승인 전 Todo 0개, 단일 승인 중복 탭 시 정확히 1개.
- [ ] 다중 항목 수정/선택/무시·다른 경로 승인 후 재승인 중복 방지.
- [ ] 공유창에서 제목·날짜를 수정한 뒤 앱/알림에서 같은 분석의 일부 승인·무시·재분석을 실행하고 공유창으로 복귀. 유효한 같은 제안의 편집만 유지하고 새 제안을 자동 선택하지 않아야 함. 조회 실패 시 저장을 막고 재확인 제공. 승인 후 조회 실패는 저장 완료로 안내.
- [ ] 저장 전 같은 사진의 재분석 확인 취소 시 기존 제안 유지, 실행 시 이전 제안/편집 교체. 빈 결과·무시한 결과도 재분석 가능.
- [ ] 일부 저장/전부 저장/저장 후 개별 삭제한 캡처는 재분석 차단. 앱과 공유창에서 승인·재분석이 겹쳐도 저장 기록과 다른 제안이 유실되지 않아야 함.
- [ ] 같은 내용의 재인코딩 사진·작은 OCR 차이에서 비슷한 기존 항목 안내. 날짜/금액/담당이 다른 별개 작업은 잘못 합치거나 버리지 않아야 함. 참고 경고의 실제 정밀도·재현율은 별도 측정.
- [ ] 비슷한 기록이 있을 때 알림 직접 추가는 검토로 전환되고 앱/공유창에서 확인 후 저장 가능. 본문 삭제·무시·만료 기록은 비교 결과에 나타나지 않아야 함.
- [ ] iOS 27 스크린샷 트리거가 전달하는 실제 이미지·파일·생성 시각 확인.
- [ ] 연속 캡처 및 직후 다른 사진 저장 시 잘못된 이미지 처리 0건.
- [ ] 단일 알림 백그라운드 승인 및 여러 항목 전면 검토 검증.

## 캡처 App Intent 검증 (코드 추가, 아직 실기기 미검증)
1. 앱 설정에서 기기 내 AI 분석 동의와 알림 권한을 직접 설정.
2. 단축어에서 이미지 선택 → ‘TTodo에서 캡처 분석’에 선택한 이미지를 전달. 촬영/메시지 시각을 모를 때 상대 마감이 확정되지 않는지 확인.
3. 분석 전 실제 Todo는 추가되지 않고 분석함에만 제안이 생성되는지 확인.
4. 한 이미지를 연속 전달해 중복 제안/알림이 생기지 않는지 확인. 실패한 이미지의 재시도는 ‘실패한 이미지 다시 분석’을 명시적으로 선택.
5. 앱이 종료/잠금/백그라운드인 경우 각각 반복. 분석 중 앱을 열어도 진행 중 작업이 실패로 변경되지 않아야 함.
6. 원문 없는 개수 안내 알림을 탭해 검토 화면으로 연결. 편집 중에는 미저장 편집을 덮어쓰지 않고, 편집 화면을 닫은 후 결과를 표시해야 함.
7. 권한 거부·동의 철회·데이터 삭제·민감 텍스트·작업 중단·빈 이미지·다른 형식 파일을 시험.
8. iOS 27 실제 스크린샷 자동화의 입력이 이미지인지 확인한 뒤 동일 Intent로 연결. 단순 사진 선택 단축어 성공을 실제 스크린샷 자동화 성공으로 간주하지 않음.

- [ ] 개인정보 처리방침·지원 연락처·권한 설명·심사자 재현 절차.
- [ ] 지원 최소 OS와 최신 OS, 서로 다른 기종, 저전력/네트워크 단절 테스트.
- [ ] TestFlight 피드백과 출시 차단 항목 모두 해결.

## 공유 메뉴 검증 (코드 추가, 실제 확장 미검증)
- [ ] 사진/파일 등 지원 호스트에서 이미지 한 장 공유 시 TTodo 표시. 비이미지/여러 이미지 입력 처리.
- [ ] AI 동의 전 분석 거부. 모델 비활성·다운로드 중·한국어 미지원·구형 OS 안내.
- [ ] 공유창에서 분석·원문 근거 확인·제목/마감 수정·선택 저장·무시 수행.
- [ ] 여러 항목 중 하나가 잘못된 경우 전체 롤백, 재승인 중복 생성 없음, 출처 share 유지.
- [ ] 분석 중 닫기/시스템 종료/호스트 종료 시 미승인 Todo 없음. 중단 분석은 복구 경로로 표시.
- [ ] 큰 캡처에서 메모리/처리 시간/확장 종료 한계 측정. 컴파일 통과를 메모리·실행 성공으로 간주하지 않음.
- [ ] 저장 후 앱·위젯·Live Activity 일치, 앱과 공유창의 동시 변경 검증.

## 알림 권한 거부 후 복구
- [ ] 첫 실행에서 아직 요청하지 않은 상태 표시와 권한 요청 버튼 확인. 자동으로 권한을 요청하지 않아야 함.
- [ ] 권한을 거부한 뒤 재요청할 수 없으면 요청 버튼 대신 기기 설정 이동으로 변경 가능. 거부 상태에서도 수동 할 일과 분석함 이용 가능.
- [ ] 기기 설정에서 알림을 켜거나 끈 뒤 앱으로 복귀하면 상태 갱신. 조용한 알림/임시 허용은 일반 허용과 구분.
- [ ] 설정 열기 또는 권한 조회가 실패해도 저장된 할 일을 사용할 수 있고, 설정 이동 실패 안내가 표시되는지 확인.
- [ ] 앱을 재실행하지 않고 보존 기간을 지난 뒤 분석함 조회/내보내기에서 만료 원문과 미저장 본문이 제거되는지 확인. 저장한 할 일과 미만료 제안은 유지.

## 사진 선택 초안 유지
- [ ] 이미지 A의 OCR을 수정하고 대화 기준일을 입력한 뒤 사진 선택창을 취소. 기존 이미지/원문 수정/기준일/이전 분석 안내가 유지되어야 함.
- [ ] 이미지 B 선택 성공 후 A의 기준일이 비워지고 B의 OCR/지문만 분석에 사용되는지 확인. B의 OCR 실패 시 A의 원문으로 B를 분석할 수 없어야 함.
- [ ] OCR/AI 실행 중 원문·기준일 입력을 수정할 수 없는지 확인. 새 이미지 교체 시 이전 임시 이미지가 정리되는지 확인.

## 열린 검토 화면의 상태 갱신
- [ ] 대기 제안의 제목/날짜/선택을 수정하고 앱을 백그라운드로 보낸 후 복귀. 같은 유효한 제안이면 수정과 선택이 유지되어야 함.
- [ ] 검토 화면이 열린 동안 다른 경로에서 제안 승인/무시/재분석 후 복귀. 최신 처리 상태와 원문을 표시하고, 새 제안은 예전 선택을 상속하지 않아야 함.
- [ ] 보존 기간 만료 후 복귀하면 캐시된 제목·설명·날짜·담당·원문이 복원되지 않는지 확인. 동의 철회 후에는 원문 근거가 다시 나타나지 않아야 함.
- [ ] 최신 상태 조회 실패 시 저장·모두 무시를 막고 재시도 가능. 빠른 복귀/재시도를 반복해 늦은 요청이 최신 결과를 덮어쓰지 않는지 확인.

## 저장 중 조작과 VoiceOver
- [ ] 홈 완료 처리 중 상세 진입/추가 체크가 비활성화되고 VoiceOver가 비활성 상태를 안내하는지 확인.
- [ ] 상세 저장/삭제·검토 승인/무시를 빠르게 연속 탭하고 시스템 닫기를 요청. 중복 작업이나 뒤늦은 닫기로 다른 화면이 닫히지 않는지 확인.
- [ ] 처리 중 제목·메모·날짜·선택을 수정할 수 없는지 확인. 저장/무시된 제안은 선택할 수 없고 비활성 상태가 전달되어야 함.
- [ ] 오래된 검토 액션이 거부되면 최신 상태를 다시 읽고, 유효한 편집만 유지하는지 확인.

## 화면 갱신 실패와 저장 성공 구분
- [ ] 입력/검토 중 앱을 복귀시키며 DB 읽기 오류를 재현. 초기화 오류 화면으로 바뀌거나 편집 초안이 지워지지 않아야 함.
- [ ] 수동 입력/승인/수정 DB 커밋 직후 목록 갱신 실패를 재현. 저장 실패로 안내하지 않고 실제 DB에는 정확히 한 번 반영되어야 함.
- [ ] 앱 목록 갱신 실패 시에도 위젯 갱신을 요청하고, 잠금화면 갱신 요청 실패가 저장 실패로 전달되지 않는지 확인. 탭 재진입 후 최신 목록과 일치해야 함.
- [ ] Dynamic Island의 compact/minimal/expanded 표시를 각각 탭. 설정 탭에서 출발해도 할 일 탭으로 연결되고, 미저장 편집·검토 중에는 해당 화면을 덮어쓰지 않는지 확인.

## 전체 삭제의 후속 정리 오류
- [ ] 전체 삭제 DB 커밋 후 공간 정리 경합을 재현. 할 일·분석·설정이 제거되고 공간 정리 오류가 알림/Activity/임시 파일 정리를 막지 않아야 함.
- [ ] Activity 종료·알림 제거·임시 파일 삭제 중 하나가 실패해도 나머지를 각각 시도하고, 미완료 정리 안내 뒤 전체 삭제로 재시도 가능한지 확인.
- [ ] DB 삭제 트랜잭션 자체가 실패하면 데이터가 부분 삭제되지 않고 오류가 전달되는지 확인. 커밋 후 정리 실패와 구분해야 함.
